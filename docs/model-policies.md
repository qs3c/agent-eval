# 模型角色、固定策略与公平性证据

本地模型池保存 API 地址、模型 ID、不可变凭据引用和可选固定策略。新实验冻结当时配置；以后编辑模型或轮换 key 不会改写已提交计划。密钥不写入配方、计划、PR 或策略日志。

模型设置中可启用固定策略，填写服务实际支持的采样/推理参数与每次尝试的请求上限。CLI 的 `model` 可包含：

```json
{
  "policy": {
    "parameters": {"temperature": 0, "top_p": 1},
    "protocols": ["openai-chat", "anthropic-messages"],
    "budget": {"max_requests": 1000}
  }
}
```

Messages 必须有对应接口；配方声明的协议与策略不匹配时预检拒绝，不切换其他模型。提供商不支持的参数由接口明确拒绝，不静默回退。上述参数是示例，不代表每个推理模型都接受 temperature/top_p。未启用策略的历史路径继续保留，但不能据此取得完整可比较认证。

## 入口角色与预算

被测主调用、子 Agent、压缩与回退通过被测入口时统一模型和参数。角色由平台启动入口绑定；客户端填写 `purpose`、`role`、`policy` 不会改变权限、模型或凭据。平台接入、守护、诊断、改进，以及 benchmark 用户模拟器、模型评分器有独立模型场景与策略身份。场景配置本身不会主动发起调用；实际执行器必须显式选择角色，平台 Agent 的执行接线见后续共享执行器章节。

请求上限针对该角色、该次尝试接收的模型操作，在容器中持久记录 reservation。中继重启不重置计数；耗尽返回 429。传输层对同一操作的有限重试沿用原有审计记录，不声称这是提供商计费请求总数的精确硬上限。不同尝试和平台执行角色分别计数。

当前不支持“保证不超过 N 美元”：价格、服务端计费及缺失 usage 无法预先可靠确定，配置 `hard_cost_usd` 会拒绝。真实调用费用缺失继续为未知；mock 的零费用只表示没有付费模型请求。

## 证据与比较

每次启用策略的尝试保留：

- `model-policy.json`：冻结配置、可信角色与摘要。
- `policy-reservations.jsonl`：已接收操作计数。
- `policy-requests.jsonl`：原始请求与应用策略后的请求。
- 原有 wire 请求、响应、usage 和原生 Agent 轨迹。
- `model-policy-report.json`：已观察调用是否一致、缺失的路径/网络证明。

实验和计划记录模型、执行资源、网络 allowlist、搜索配置及 JEV 模型/阈值的指纹；指纹是配置身份，不是运行时覆盖证明。对比页显示已观察一致性、证据数量与不可比较原因，仍可查看描述性的逐题结果。

目前四种内置 Agent 的固定策略原生运行和取消回收已经通过 mock Docker 验收，但尚未认证所有内部模型分支与网络旁路。因此它们仍不自动取得 Comparable。相同 model ID 也不能证明提供商服务端权重永久不变。

## 搜索边界

原有搜索/JEV 路径保留，deny、审查不可用和提供商失败仍分别记录；审查只覆盖进入审查入口的搜索。浏览器、shell 和自带搜索不自动受 JEV 约束。

固定模型策略入口当前拒绝辅助搜索端点，配置中同时启用固定策略与搜索审查/外部搜索会明确报错，防止绕过独立预算。需要搜索的实验继续使用原有入口并显示覆盖限制；不能以此宣称完整模型公平性已通过。
