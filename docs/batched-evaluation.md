# 有界批次测评

配置 `batch` 后，一个实验先冻结全部题目元数据、模型配置和 Agent 产物，再按批准备镜像。SWE Verified 的 80 题、两个 Agent 仍是一个 160 次尝试的实验；批次不改变成绩分母或外部辅助标记。

```json
{
  "concurrency": 2,
  "batch": {
    "size": 20,
    "prepare_swe": true,
    "official_regrade": true,
    "retain_count": 3,
    "retain_gib": 20,
    "retain_hours": 24,
    "min_free_gib": 20
  }
}
```

`batch` 默认关闭。开启但未指定守护时使用 observe 期限兜底；指定 assist 时继续使用冻结的守护策略。SWE 准备和复评要求 resolved 类型 benchmark；其他 Harbor 单阶段任务可以使用批次执行而关闭这两个选项。

每批按 `preparing → running（逐个 Agent、各自使用任务并发）→ regrading → cleaning → completed` 执行。尝试本批独立 SWE harness 4.1.0 复评后处理镜像。官方报告必须覆盖本批精确 ID 集合；复评异常或报告不完整时，将 `official_regrade.status` 记为 `failed` 并保留错误，继续清理和下一批作答。批次 `completed` 表示作答与清理完成，不表示官方复评通过；控制台单独显示待处理复评批次。正常 unresolved 和 empty patch 保留在成绩分母中。

延期复评保留冻结任务、镜像 digest、runtime archive、补丁和已有复评证据；清理可能删除本批镜像，后续复评需按固定来源重新准备镜像。磁盘不足、准备失败、作答调度错误、清理失败及取消操作仍停止流水线，不因复评容错而忽略。

## 证据和空间

- `manifest.json` 固定模型/Agent/来源配置，并记录每批准备后的任务哈希、镜像 digest 和 runtime archive hash。
- `selection.json` 保存来源抽样与排除清单。任务内容、日志、补丁、守护证据与历史实验都保留。
- `shared-runtime/<sha256>.tar` 在每个冻结目录独立保存一份，各题的 archive 使用目录内硬链接；源目录变化不会改变冻结副本。任务路径和原有任务哈希定义保持兼容。
- `batch-state.json` 保存批次、阶段和运行进程身份；控制台详情显示当前批次。
- `batches/NNN/official/` 保存仅含本批 ID 的 predictions、dataset、命令日志和原始官方报告；`official-summary.json` 汇总 observed/expected 与原始报告位置。
- `batches/NNN/cleanup.json` 记录实际镜像删除返回值、容器引用保护、构建缓存清理和前后空闲字节数。

20 是任务数上限，不是固定磁盘容量保证。准备每题和进入 Agent 阶段前检查余量；不足时明确停止，不开始新的付费作答。Docker 层共享、单题镜像大小、诊断归档及其他服务仍影响峰值。清理只删除当前批记录的 SWE digest/tag 和 Harbor `hb__` 构建标签；被其他容器引用或不属于这些标签的镜像保留。清理未使用构建缓存可能使以后构建变慢，不删除生产镜像、容器、网络或数据卷。

## 异常保留

有异常、外部辅助介入或缺少关键日志/补丁/评分报告时，先停止目标容器，再把 `/testbed` 复制为 `retained-workspace.tar`。这是离线工作区文件快照；原容器、API 凭据所在的 installed-agent 目录和 container Env 不保留。已知 .env、key/token/secret/credential 文件名、凭据目录及符号链接会过滤，跳过数量与失败原因写入 `retention.json`。不承诺恢复原进程、内存、整个根文件系统或被过滤文件。

正常终止且证据齐全的题无需快照，包括 reward=0。所有原容器最终停止、精确删除以释放槽位。每个实验最多 3 份、20 GiB；归档时留 2 GiB 磁盘余量，单次快照最多 120 秒。超过配额淘汰最旧快照；24 小时期限在下一次归档时检查，不是后台定时器。超限、源工作区不可用、复制失败或清理失败均记录，不能解释为完整现场已保留。`retain_count=0` 关闭工作区归档，仍保留现有日志与异常记录。

## 恢复

```sh
agent-harness-eval run experiments/swe-live-80-assist.json --output artifacts/swe-live-80 --resume
```

正式运行应使用已冻结的配置文件恢复（当前本地实验为 `.cache/swe-live-80/config.json`）。恢复需要同一配置、完整 provenance、未修改的冻结任务及 Agent 产物；已完成批次跳过，已有终态尝试（包括失败）计入次数而不重跑。存在匹配任务的无结果尝试时拒绝自动重跑，要求先检查原进程和容器；准备阶段私有事务可按原哈希回滚。清理失败后的恢复可再次运行独立评分/清理，不重复被测 Agent 调用。已完成批次中的失败复评需单独补跑，`--resume` 不会自动重放这些批次，也不会把复评失败改成成功。

## 验证

单元测试覆盖批次顺序、统一成绩、恢复跳过、冻结文件篡改、共享 archive 独立性、当前批复评覆盖和引用保护。真实禁网 Docker 验收覆盖工作区归档与凭据过滤；真实 Harbor 两批四次正负对照全部按预期评分。独立 SWE harness 使用 `pylint-dev__pylint-6903` 的基准补丁得到 resolved=1、errors=0；这属于离线评分连通性检查，不计为 Agent 成绩。

## 自动重试与手动补评

官方复评按“题目 × Agent × attempt”执行，每项最多尝试 3 次。网络连接重置、连接/读取超时等临时故障在 5 秒、15 秒后重试；单次 harness 进程期限为 1800 秒，超时终止整个进程组。配置错误、报告覆盖不完整直接保留为失败；测试正常运行后的 unresolved 不触发重试。复评失败继续后续作答。

详情页每批只有一个「复评未完成题目」按钮，另有「复评全部未完成批次」。重复提交同一批次返回同一个排队或运行任务；不同批次按照提交顺序排队。作答流水线尚未结束时手动任务等待，避免与镜像清理冲突。批次任务串行出队，任务内部同时执行两项复评。自动批次复评、手动补评及 `swe-regrade --execute` 共用同一 Unix 用户下的全局锁与两个执行槽位，跨工作区和控制台实例也不叠加并发。

队列保存于 `~/.cache/agent-harness-eval/regrading/queue.sqlite3`。服务重启时，确认旧复评进程已释放继承的锁后，将原运行任务标记为 interrupted，等待再次点击；queued 任务继续排队。失败任务可重新提交。补评检查冻结任务哈希；仅复评，不重新执行被测 Agent。

`batches/NNN/official/progress.json` 保存逐项状态和当前日志路径；`units/` 为每次执行生成独立目录，保存输入、日志、官方报告与执行记录。成功项仅在输入哈希、报告哈希及报告覆盖检查一致时跳过。`export-evidence-*.json` 保存本次导出追溯信息；原有失败日志和冻结实验记录保留。`official-summary.json` 单独汇总官方结果，Harbor 原始分数不变。旧版 `deferred.json` 和失败状态在页面显示为待处理，首次补评建立上述逐项记录。

本次本地验证：全量 Python 回归 279 passed、10 skipped；实验列表和 RSI 的 30 项前端测试通过；Ruff、JavaScript 语法及 diff 检查通过。既有守护窗口测试原先随机选取第一条 incident，可能误选超时清理记录；现按 `no_observed_progress` 选择诊断记录，并分别验证诊断完成、到期禁止 exec 与超时清理。未进行真实 SWE 联网复评或部署验收。
# 镜像生命周期

做题容器和官方复评容器独立创建，结束后归档证据并按保留策略释放容器。官方 SWE 4.1.0 的测试与评分逻辑不变；启动适配器只关闭评分进程内的镜像删除和全局清理扫描，并记录使用的实例镜像，交由批次协调器统一回收。

每个批次准备前登记持久租约。运行失败、中断或复评失败不释放租约，保留镜像供恢复；手动复评全部完成后释放。协调器采用保守策略：同一 Unix 用户仍有任何正在运行或待恢复的批次时，暂缓所有已登记批次的镜像回收；最后一个消费者完成后统一处理。独立 CLI 复评也通过进程继承的共享锁与镜像回收互斥。

未恢复批次可能使镜像占用持续增长；已有磁盘余量门槛会停止启动新批次，不会为了腾空间静默删除待复评镜像。此机制覆盖使用新版协调器登记的工作；升级前遗留任务或外部手工 Docker 清理不在租约管理范围内。原始 trace、补丁和报告不随镜像清理删除。

Docker 检查仅在明确返回不存在时视为幂等成功，服务不可用、权限失败等异常保留租约并报错。镜像仍被容器引用时保留 ready 租约，后续协调回收再次尝试；不会把跳过删除记成已完成回收。取消后不再恢复的批次仍需管理员确认后处理，当前不按时间自动释放待恢复租约。

2026-10-15 部署前验证：生命周期、批次、复评、SWE 和 Web 的 39 项回归通过；全量测试首次为 283 passed、9 skipped、1 failed，失败原因是隔离测试目录漏传 integrations 补丁，补齐后该测试模块 12 项全部通过。固定 SWE 4.1.0 启动适配器命令行兼容性检查通过；未重新执行付费 Agent 实验。
