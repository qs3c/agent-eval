# Agent Eval 本机评测控制台设计

状态：已实现并完成本地验收，见 WEB_VALIDATION.md。日期：2026-10-11。

## 目标与方案

在现有评测工作台上增加浏览器入口，完成创建实验、查看进度、对比结果三个流程。首版面向本机单用户，通过 `agent-eval serve` 启动，默认仅监听 `127.0.0.1`。

采用 FastAPI 提供管理 API 和同源静态 HTML/CSS/JavaScript 页面；使用 SQLite 保存控制台运行状态和冻结配置，现有 artifacts 文件继续保存原始证据。运行器以独立子进程调用现有 CLI，Harbor 继续管理 Docker 和 trial，不替换其调度。

备选：纯报告页面不能创建实验；React + 独立服务 + 外部任务队列能支持更复杂的平台，但首版增加的构建、部署与运维成本不必要。选择同服务页面与 API，后续可保持接口并替换前端。

## 页面与操作

1. 实验列表：展示历史和新运行的名称、benchmark、模型模式、Agent、时间、状态、已完成 trial 数；提供空状态和加载失败提示。
2. 创建实验：从仓库 experiments 模板选择，编辑实验名称、Agent 子集、任务子集、重复次数、并发、超时、CPU 和内存。展示预计 trial 数与依赖检查结果。首版不允许页面任意填写 Python import path、服务器文件路径或启动命令。
3. 运行详情：显示冻结配置、运行状态、已产生的 trial、有限长度的执行日志及结果表；轮询刷新。没有阶段证据时显示运行中，不伪造百分比或预计结束时间。
4. 结果对比：选择两个运行，展示 Agent 的评分、异常、缺失、耗时和用量。只有 benchmark、任务内容哈希、模型条件、attempts 和主指标一致时提供直接配对比较；其他情况展示差异并明确不可直接比较。不混合不同 benchmark 总分，不因单次 smoke 宣称排名。

界面使用中文，桌面优先并适配窄屏；表格、状态和操作层次清晰，使用原生可访问表单，错误落在具体字段或运行记录上。

## API 与数据流

- `GET /api/templates`：返回经过过滤的实验模板及依赖可用性。
- `GET /api/runs`、`GET /api/runs/{id}`：列表、详情、状态与报告摘要。
- `POST /api/runs`：接收模板 ID 与允许修改的字段；复用现有配置校验，冻结配置并创建 queued 记录，返回运行 ID。
- `GET /api/runs/{id}/logs`：有大小限制的日志尾部；不会返回任意路径文件。
- `GET /api/compare`：比较选定的两个运行及配置一致性。

浏览器 → API 校验 → SQLite 记录与配置快照 → 后台 worker → 现有 CLI/Harbor → artifacts → API 读取结果 → 页面展示。

模板中的相对路径先按原模板所在目录解析再冻结，防止配置移动后任务或 Agent 包路径失效。现有 CLI 命令保持可用。

## 运行生命周期与恢复

采用 queued、running、completed、failed、interrupted 状态。一次只启动一个实验；该实验内部仍使用配置的 Harbor trial 并发。API 请求只负责提交，不等待实验完成。

SQLite 事务保证领任务唯一；服务只运行一个 worker。通过实例锁阻止两个服务同时管理同一状态目录。子进程用参数数组启动，不拼接 shell 命令；输出写入独立日志文件。退出码及输出完整性决定状态，报告中保留 trial 错误，不能把执行进程成功等同于所有题目通过。

服务正常关闭时停止领任务，向所属进程组发终止信号并等待清理，必要时有界强制结束。重启时将遗留 running 标为 interrupted，禁止自动重跑；有遗留执行进程或容器风险时先阻止新执行并提示处理。首版不承诺断点续跑，也不新增页面取消按钮。

## 历史数据与结果语义

扫描 artifacts 下有 manifest 的运行，将其登记为历史记录，不改写原始日志或验收文件。历史文件不完整时明确标记结果缺失，不根据目录名推断完成。服务端只接受登记的运行 ID，文件读取限制在对应运行目录且拒绝越界和符号链接逃逸。

沿用 report.json 的指标与未知值约定。费用未知显示“未知”；tokens 不转换为账单金额。ATIF 标明其覆盖范围，不能称为无损轨迹。官方 SWE 复评与 Harbor 内置评分分别标识；首版不自动从结果页面发起官方复评，也不把外部复评文档中的结论当作当前报告字段。

## 模型执行与边界

页面可查看 live 历史和模板。新 live 运行必须由服务启动选项显式开启，凭据仅从服务进程环境注入；提交表单需明确选择现有 unbounded 费用策略。开发验收只用离线对照和模拟模型，不自动执行新的付费评测。

默认本机使用，不提供公网部署、账号权限或多人协作。写接口检查 Host 和 Origin，拒绝跨站写入；日志展示使用纯文本并过滤凭据。静态资源与 API 同源，不开放跨域。不会将 .env、状态数据库和运行日志提交到 Git。

## 文件与依赖变化

新增独立的 web 服务、运行管理模块及静态资源目录；在 cli.py 增加 serve 子命令，在 pyproject.toml 和 uv.lock 中固定所需 Web 依赖，确保资源进入安装包。新增控制台测试、README 启动说明和验收记录，沿用现有 config、report 和 runner 逻辑。

## 验收标准

- 原有 23 项测试继续通过。
- API 测试覆盖模板字段白名单、无效配置、路径越界、跨站写入、缺失结果、重复领任务、进程失败和重启中断。
- 浏览器可完成选择模板、提交离线实验、自动查看进度和结果；刷新页面后运行仍可查询。
- 实际执行一次文件任务正负对照，oracle/positive 为 1、nop 为 0；Docker 不可用时据实说明，不能用模拟状态代替真实执行验收。
- 历史运行可浏览；两份兼容报告可对比，不兼容报告有明确提示；未知费用不显示为零。
- 检查桌面和窄屏布局、键盘操作、空状态和错误状态；交付本机可用页面地址与验证结果。
